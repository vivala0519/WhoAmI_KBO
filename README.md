# 2026 야구 선수 맞히기

앱인토스용 하루 한 문제 선수 추리 게임이다. **2026-11-11부터 등번호와 원화 환산 연봉이 있는 상위 100명**을 출제·검색 대상으로 사용한다. 연봉 동률은 숫자 선수 ID 오름차순으로 선정하며, 100위 기준선은 3억 원이다. `src/players.json`의 기존 250명은 이전 문제·기록·수집 카드를 복원하는 원본으로 보존한다. 1군 출전 여부와 앱 배포 권리는 아직 확인되지 않았다.

단서는 구단·포지션·투타유형·출생연도·등번호·키·연봉 7가지다. 투타유형은 사용자 제공 `kbo_players_2026_all.json`에서 기존 선수 ID에 결합했다. 11월 10일까지의 날짜별 정답과 기존 기록은 유지하며, 11월 11일부터 기존 일정의 순서를 유지한 상위 100명을 100일 주기로 출제한다. 이전 버전에서 같은 날 시작한 문제가 새 일정과 다르면 진행 중인 문제만 새 답으로 시작하고 누적 기록·수집 카드는 보존한다. 이미 완료한 문제는 다시 열지 않는다.

## 로컬 실행

```powershell
npm ci
npm run dev
```

모바일 폭에서 `http://127.0.0.1:5176/`을 연다. 타입 검사와 웹 빌드는 `npm run build`, 운영 프로모션을 포함한 앱인토스 번들은 `npm run build:toss`로 만든다.

## 실제 데이터 준비

[DATA_SOURCES.md](./DATA_SOURCES.md)에 두 CSV의 결합·선정 기준과 검증 결과를 기록했다. [원본 선정 보고서](./data/top250-selection-report.json)의 1~100위를 현재 선수풀로 사용한다. `scripts/select-kbo-top250.mjs`는 보존한 원본 250명을 검증하며, `src/game.ts`에서 연봉 순으로 상위 100명을 선정하고 전환 날짜를 적용한다.

결과 공유는 PL 프로젝트의 제목·날짜·성공 여부·누적 플레이·승률·평균 시도·현재 연승·앱 링크 형식을 따른다. 단서 색상은 KBO의 초록·노랑·검정 7칸을 사용한다.

제공 CSV의 출처는 KBO 선수 조회·상세 페이지다. [KBO 이용약관](https://www.koreabaseball.com/Etc/Policy.aspx)은 허가 없는 대량 자동 수집과 수집 데이터 재배포를 제한하므로 이 번들은 업로드하지 않았다. 공개 전에는 광고가 있는 미니앱에서의 저장·가공·배포 권한과 2026 1군 출전 여부를 확인한다.

## 앱 설정

- UI는 형제 프로젝트 `WhoAmI`의 화면 구조·타이포·라이트/다크 테마를 기준으로 구성했다. 첨부 야구공을 사용하는 파티클 효과는 [파티클 안내](./docs/particle-ball.md)를 참고한다.

- `apps-in-toss.config.ts`의 `appName: "whoami-kbo"`는 콘솔에 등록된 오늘의 야구선수 앱 식별자다.
- 개발 중 보상형 광고는 공식 테스트 ID를 사용한다. 운영용 그룹 ID는 `.env.example`을 참고해 `VITE_TOSS_REWARDED_AD_GROUP_ID`로 설정한다. 새 앱의 보상 단위는 `기회`, 수량은 `1`이다.
- 진행 상태, 기록, 도감과 테마는 이 앱 전용 브라우저 로컬 저장소 키를 사용한다. 기기 간 동기화는 없다.
- 선수 사진과 구단 로고는 사용하지 않는다.

## 보상형 광고로 추가 도전

- 기본 기회는 5회다. 5번째 오답 후 광고를 끝까지 시청하면 6번째 기회가 열리고, 이후 오답에서도 광고 1회당 기회 1회를 추가한다. 한 문제에서 광고는 최대 3회, 총 시도는 최대 8회다.
- 광고를 중간에 닫거나 표시·로드에 실패하면 기회를 추가하지 않는다. `userEarnedReward`에서만 한 번 지급하며, 이전 광고의 중복 이벤트나 날짜가 바뀐 뒤 도착한 보상은 무시한다. 광고를 선택하지 않고 정답을 확인할 수도 있다.
- 광고는 미리 로드하고, 닫힘·표시 실패 뒤 다음 광고를 준비한다. 로드 실패 시 `광고 다시 불러오기`로 재시도한다. 광고 재생 중에는 중복 실행과 정답 확인을 막는다.
- 콘솔의 `후엠아 KBO 보상형` 그룹(`ait.v2.live.e5217cdf0cb74e89`)은 활성 상태이며 보상 설정은 `기회 1개`다. `.env.local`의 `VITE_TOSS_REWARDED_AD_GROUP_ID`에 연결했다. 이 파일은 Git에서 제외되며 새 환경에서는 `.env.example`을 복사한다.
- 개발 서버는 항상 `ait-ad-test-rewarded-id`를 사용한다. 별도 실기기 광고 테스트 빌드는 `.env.local`의 `VITE_TOSS_AD_TEST=true`로 만들고, 운영 빌드에서는 `false`로 둔다. 프로모션 테스트 설정과는 별개다. 테스트할 때 실제 광고 ID로 노출·클릭을 발생시키지 않는다.
- [공식 전면·보상형 광고 문서](https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/interstitial-rewarded-ad)의 이벤트 흐름을 따른다. 실광고 렌더링과 시청 완료 동작은 토스 앱의 QR 테스트에서 확인한다.

## 5일 연속 성공 프로모션

- 2026-11-06~2026-12-31(한국 시간)에 오늘의 챌린지를 5일 연속 성공할 때마다 500 토스 포인트를 지급한다. 10일·15일 연속 성공에도 각각 한 번 지급하며, 실패하거나 하루를 건너뛰면 연속 기록을 다시 시작한다. 시작일 이전 성공은 포함하지 않는다.
- 등록된 프로모션 코드 `01M6P5RVJQ58D3G8SKJQ9QMMBG`와 고정 금액 500을 SDK 3.9의 `Promotion.grantReward`에 전달한다. [공식 프로모션 문서](https://developers-apps-in-toss.toss.im/documentation/common/growth/promotion)를 기준으로 연결했다.
- 지급 호출 전에 이 앱의 별도 지급 기록을 저장한다. 계정·프로모션 코드·달성 구간별로 중복 실행을 막으며, 하루 지급 한도는 500이다. 응답이 불명확하면 재지급하지 않고 포인트 내역 확인을 안내한다. 지급이 명확하게 거절된 경우에만 재시도할 수 있다.
- 프로모션 참여 기록은 익명 사용자 식별키에 연결한다. 당일 성공을 확인할 때 해당 계정 소유로 기록하고, 다른 계정이 같은 기기의 기존 기록을 가져가 보상받을 수 없게 한다. 이전 날짜를 소급해서 다른 계정에 연결하지 않는다.
- 게임 기록과 지급 기록은 이 기기의 로컬 저장소에 있다. 기기 변경·저장소 삭제에 걸친 중복 지급 방지와 기록 동기화는 서버 검증이 필요하다.
- 개발 서버와 `npm run build:toss:promo-test`는 `TEST_` 프로모션 코드와 테스트 광고 ID를 사용한다. QR 테스트로 열고 첫 화면에서 **테스트 지급 확인**을 누르면 된다. `npm run build:toss`는 프로모션 테스트 설정을 끄고 운영 코드로 빌드한다. 두 명령 모두 `whoami-kbo.ait`에 저장하므로 업로드 전에 원하는 명령으로 다시 빌드한다.
- 콘솔에서 **승인 완료(APPROVED)·테스트 완료(isTested=true)·시작 전(SCHEDULED)**을 확인했다. 실제 포인트 지급에는 콘솔에서 캠페인을 시작해야 한다. [공식 운영 가이드](https://developers-apps-in-toss.toss.im/guide/marketing/promotion)의 게임 결과 기반 보상 제한이 현재 연속 성공 조건에 적용되는지는 운영 전에 앱인토스에 확인한다.
- 예산 소진 시 조기 종료할 수 있다. 지급 결과가 불명확한 건은 콘솔 지급 내역과 대조한 뒤 처리한다.
